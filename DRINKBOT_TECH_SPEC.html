1. TỔNG QUAN DỰ ÁN & PHẠM VI 1. PROJECT OVERVIEW & SCOPE

1.1. Bối cảnh & Mục tiêu (Context & Objectives) 1.1. Context & Objectives

Dự án xây dựng một trợ lý ảo thông minh (Chatbot) ngành F&B tư vấn cá nhân hóa (cà phê, trà, sinh tố detox, protein shake) và tiếp nhận đơn hàng tự động, đồng thời đáp ứng các tiêu chuẩn khắt khe về MLOps: thu thập thực thể, quản lý phiên bản prompt/model, quan sát latency/chi phí và kiểm thử hồi quy.

The project delivers an intelligent F&B conversational assistant that recommends personalized beverages (coffee, tea, detox juices, protein shakes) and handles orders while adhering to strict MLOps standards: entity collection, prompt/model version control, latency/cost observability, and automated regression evaluations.

1.2. Mục tiêu kỹ thuật cốt lõi (Core Technical Goals) 1.2. Core Technical Goals

  • Thu thập thực thể (Entity Collection): Bắt buộc thu thập và lưu trữ thông tin khách hàng: Số điện thoại (Phone), Tên (Name), Địa chỉ giao hàng (Address) vào PostgreSQL. Entity Collection: Collect and persist core customer entities: Phone Number (Regex VN), Name, and Delivery Address into PostgreSQL.
  • An toàn dị ứng tuyệt đối (Allergen Hard Guardrails): Loại trừ 100% nguy cơ ảo giác dị ứng bằng mã nguồn Python trước khi đưa vào context của LLM. Allergen Safety Guardrails: Eliminate 100% LLM hallucination risks regarding allergens via strict code-level filtering in Python prior to LLM context ingestion.
  • Phê duyệt 2 tầng (Human-in-the-Loop): Mọi hành vi nhạy cảm (Tạo đơn hàng, cập nhật dị ứng) đều ở mức pending và yêu cầu người dùng xác nhận rõ ràng. Two-Stage Human-in-the-Loop: Irreversible actions (Order placement, profile/allergy updates) remain pending until explicitly approved by the user.
  • Giám sát chi phí vi mô (Observability): Ghi vết chi tiết từng câu chat: Model, Prompt Hash, Token In/Out, Chi phí USD và Latency qua Langfuse Telemetry. Granular Observability: Log structured telemetry per chat turn: Model Name, Prompt Hash, Tokens In/Out, USD Cost, and Latency via Langfuse Telemetry.
  • Prompt Versioning & Hot-swap: Lưu trữ Prompt trong Database với mã băm SHA256; hỗ trợ kích hoạt và Rollback tức thì mà không cần restart server hay deploy lại code. Dynamic Prompt Versioning: Database-backed Prompt Registry with SHA256 drift detection; instant runtime hot-swap/rollback without server restarts.

1.3. Ngoài phạm vi hiện tại (Non-Goals / Gaps) 1.3. Non-Goals / Current Gaps

  • AWS Bedrock qua VPC Endpoint: Hiện tại hệ thống kết nối trực tiếp OpenAI / Gemini API và mô hình cục bộ Ollama; tầng Private VPC Endpoint dành cho phase tiếp theo. AWS Bedrock via VPC Endpoint: Direct connection to OpenAI / Gemini API and local Ollama is active; AWS Bedrock VPC Endpoint is scheduled for the next phase.
  • Cổng thanh toán trực tuyến: Đơn hàng lưu trạng thái placed vào cơ sở dữ liệu, chưa tích hợp cổng thanh toán trực tiếp (Stripe/VNPay). Payment Gateway: Orders transition to placed status in the database without direct payment gateway integration.

Agent được cấu hình theo vòng lặp hữu hạn (tối đa 4 iterations) liên kết 3 công cụ cốt lõi:

The agent runs a bounded tool-calling loop (maximum 4 iterations) bound to 3 primary tools:

  • recommend_drink: Tra cứu menu đồ uống đã được lọc sạch chất dị ứng của người dùng. recommend_drink: Queries menu items that have been strictly filtered against customer declared allergens.
  • update_profile: Ghi nhận sở thích/dị ứng mới → tạo PendingPreferenceChange. update_profile: Stages preference/allergy modifications into PendingPreferenceChange.
  • order: Kiểm tra an toàn dị ứng lần 2 → tạo đơn hàng ở trạng thái pending. order: Executes secondary allergen check → creates an Order in pending status.

4. THIẾT KẾ API CỐT LÕI (CORE API SPECIFICATIONS) 4. CORE API SPECIFICATIONS

4.1. Nhóm Endpoints Nghiệp Vụ Chat & Ordering 4.1. Chat & Order Endpoints

  • POST /api/auth/register: Đăng ký người dùng mới (phone, name, address) → trả về JWT token. User registration (phone, name, address) → returns JWT session token.
  • POST /api/chat: Gửi tin nhắn người dùng đến Agent → trả về tin nhắn trợ lý kèm metadata và pending state. Send message to Agent → returns assistant reply, tool executions, and pending order preview.
  • POST /api/chat/confirm-order: Xác nhận đơn hàng pending chuyển thành placed. Confirms a pending order and marks it as placed.

4.2. Nhóm Endpoints MLOps Telemetry & Prompt Management 4.2. MLOps Telemetry & Prompt Registry Endpoints

  • GET /api/telemetry/traces: Lấy 20 traces gần nhất kèm token, latency, chi phí cho Frontend Inspector. Retrieves recent execution traces with token consumption, cost, and latency for Frontend Inspector.
  • GET /api/telemetry/prompts: Lấy danh sách toàn bộ phiên bản prompt và hash SHA256. Fetches all registered prompt versions and active SHA256 hashes.
  • POST /api/telemetry/prompts/activate: Hot-swap kích hoạt phiên bản prompt tức thời tại runtime. Hot-swaps active prompt version at runtime without server restart: 
    // Request Body
{ "version": "2.0.0-cuc-mich" }

// Response Body
{ "status": "activated", "active_version": "2.0.0-cuc-mich", "prompt": { ... } }
  • POST /api/telemetry/evals/run: Thực thi automated benchmark suite trên dataset chuẩn hóa. Executes automated benchmark evaluation against standardized dataset.

6. BẢN GHI QUYẾT ĐỊNH KIẾN TRÚC (ARCHITECTURE DECISION RECORDS - ADR) 6. ARCHITECTURE DECISION RECORDS (ADR)

ADR-01: Lọc dị ứng bằng mã nguồn Python thay vì giao phó cho Prompt LLM ADR-01: Hardcode Allergen Filtering in Python vs. Prompt-based LLM Enforcement

Status: Accepted & Implemented

Bối cảnh (Context): Khách hàng có thể bị sốc phản vệ hoặc tử vong nếu dùng phải đồ uống chứa chất dị ứng. LLM dù thông minh vẫn có xác suất hallucination hoặc bị prompt injection.

Context: Allergen exposure can cause severe allergic reactions or anaphylactic shock. Prompt instructions to LLMs cannot guarantee zero hallucinations or complete safety against adversarial injection.

Quyết định (Decision): Xây dựng logic lọc dị ứng hoàn toàn bằng Python (backend/app/services/recommendation.py). Hệ thống tự động mở rộng dị nguyên (ví dụ: "dairy" → milk, butter, cheese, whey) và loại bỏ triệt để các món vi phạm trong Menu trước khi gửi danh sách vào prompt LLM. Tool order cũng kiểm tra lại một lần nữa bằng code.

Decision: Enforce allergen exclusion strictly in Python code (backend/app/services/recommendation.py). The service expands declared allergies into ingredient sets (e.g. "dairy" → milk, butter, cheese, whey) and eliminates non-compliant items before the LLM ever sees the menu. The order tool performs a secondary validation in code.

Hệ quả (Trade-offs): Đạt tỷ lệ an toàn tuyệt đối 100%, bảo vệ tính mạng khách hàng; đổi lại backend phải duy trì bảng từ điển dị nguyên.

Trade-offs: Guarantees 100% allergen safety regardless of LLM output; requires maintaining an allergen-ingredient mapping in the backend.

ADR-02: Quản lý Prompt động qua Database và Cơ chế Hot-swap Runtime ADR-02: Database-Backed Prompt Versioning with Runtime Hot-Swap and Drift Detection

Status: Accepted & Implemented

Bối cảnh (Context): Ban đầu prompt được hardcode trong code. Mỗi lần tinh chỉnh prompt, A/B test hoặc thử nghiệm phiên bản mới (như bản v2.0.0-cuc-mich) phải rebuild Docker image hoặc deploy lại code, gây downtime.

Context: Hardcoding prompt templates in source code requires full rebuilds and redeployments to test copy updates, A/B test variants, or personality experiments (e.g. v2.0.0-cuc-mich), causing service disruption.

Quyết định (Decision): Xây dựng bảng PromptVersion trong PostgreSQL kết hợp in-memory cache registry. Tạo mã băm SHA256 (12 ký tự) để nhận diện drift cấu hình. Cung cấp API /api/telemetry/prompts/activate cho phép Admin bấm đổi prompt hoặc rollback tức thì ngay trên UI.

Decision: Implement a PostgreSQL PromptVersion entity synchronized with an in-memory registry. Generate SHA256 hashes (12 chars) to detect template drift. Expose /api/telemetry/prompts/activate to hot-swap or rollback active prompts dynamically without downtime.

Hệ quả (Trade-offs): Thay đổi văn phong bot trong 1 giây mà không gián đoạn dịch vụ; đổi lại phải có cơ chế đồng bộ giữa Database và cache in-memory.

Trade-offs: Enables zero-downtime prompt rollback and instant A/B experimentation; introduces cache synchronization requirements across worker instances.

ADR-03: Cổng Phê Duyệt 2 Tầng (Two-Stage Human-in-the-Loop) ADR-03: Two-Stage Human Confirmation Gate for Irreversible Actions

Status: Accepted & Implemented

Bối cảnh (Context): Đặt hàng liên quan đến tài chính và giao vận. Nếu để LLM tự quyết định đặt hàng khi khách chỉ hỏi vu vơ, khách hàng sẽ bị tạo đơn nhầm lẫn.

Context: Placing orders involves monetary transactions and logistics. Allowing an autonomous LLM to finalize orders based on conversational intent frequently results in accidental purchases.

Quyết định (Decision): Tool order chỉ tạo đơn ở trạng thái pending. UI hiển thị thẻ xác nhận và đơn hàng chỉ chuyển sang placed khi khách hàng chủ động bấm nút "Xác nhận đặt hàng" trên màn hình.

Decision: The order tool is restricted to creating orders in a pending state. The UI renders a confirmation card requiring an explicit customer click before the order transitions to placed.

Hệ quả (Trade-offs): Loại bỏ 100% đơn hàng rác và hiểu nhầm ý định; đổi lại thêm một bước thao tác xác nhận cho người dùng.

Trade-offs: Completely prevents unintentional transactions; adds one explicit confirmation click to the customer user experience.
